# Whole-Pipeline Audit Report

## Overall verdict

The current repository is internally well organized enough to reproduce the provisional catalog exactly: the clean block files, per-burst fit products, combined catalog, and machine tables account for **106 bursts and 1,057 time-resolved bins with no missing or duplicate bins**. Several findings from the June 9 audit are genuinely fixed, including the decisive-BB gate, the rise-phase HTS/IT classifier, the D'Agostini likelihood, and the major correlation-figure layout problems. The pipeline is nevertheless **not yet scientifically submission-ready**. The most consequential remaining problems are that the sample-selection code is not the stated Busby procedure, the human-background output is not consumed by the production refit driver, the binning likelihood is only a Gaussian/raw-count approximation, the headline Ep-kT calculation mixes parameters from different spectral fits, DSBPL optimization failures remain common, and the locked Delta-AIC=10 framework is not the headline result. No finding below is a whole-project BLOCKER, but the HIGH findings require correction or an authoritative rerun before the paper numbers can be defended to an ApJ referee.

## BLOCKER

No BLOCKER-severity finding was confirmed.

## HIGH

### H1. The single-pulse sample is not generated by the stated Busby & Lazzati procedure

**Evidence.** The initial catalog stage imposes an undocumented `T90 > 2 s` cut (`scripts/01_build_sample.py:18-19`, `scripts/01_build_sample.py:51-58`), although the manuscript says no T90 restriction is imposed (`paper/two_break.tex:153-158`). The morphology code then uses only the first detector in catalog-mask order (`scripts/03_horizontal_line.py:251-263`), while the detector list itself is merely the ordered BCAT bit mask, not a brightness ranking (`scripts/01_build_sample.py:82-102`). Busby & Lazzati used two brightest NaIs; this implementation neither measures brightness nor combines/checks two detectors. It also claims 120 equal ROI bins but normally constructs bins using `T90/48` and only falls back to 120 equal bins in a short-data edge case (`scripts/03_horizontal_line.py:92-108`), whereas clipped ROIs should still be divided into exactly 120 bins.

**Impact.** The current 106-burst membership is not reproducibly justified by the cited selection method. All 106 selected bursts have T90 > 2.944 s, so the paper's statement that the sample includes short and long bursts is false for the current catalog. The number of bursts that would change under a faithful two-detector, 120-bin rerun cannot be inferred without rerunning selection.

**Fix.** Remove or explicitly justify the T90 cut; compute signal brightness for all eligible NaIs, run the published algorithm on the two brightest detectors with exactly 120 bins over the clipped ROI, define how the two detector classifications are combined, and freeze the input catalog release/query date.

### H2. The human-reviewed background catalog is disconnected from the production driver

**Evidence.** The picker writes `results/background_intervals.ecsv` (`scripts/30_background_picker.py:61-66`, `scripts/30_background_picker.py:492-496`), but the full-sample driver hardcodes `results/background_intervals_clean.ecsv` and passes that file to the engine (`scripts/29_refit_clean.py:15-20`, `scripts/29_refit_clean.py:34-37`). Thus completing the advertised human review and rerunning script 29 still uses the automatic catalog unless files/code are manually changed.

**Impact.** The promised authoritative background pass cannot enter the stated production path. A user can believe the human selections were fitted while all 1,057 bins still use the automatic windows.

**Fix.** Make the background input an explicit required CLI argument, write the authoritative run to a fresh output root, and stamp the exact background-file hash in every per-burst JSON.

### H3. The automatic background catalog still contains invalid and rule-breaking windows

**Evidence.** The generator targets 80 s but permits one side to be zero and validates only total width plus one side >=40 s (`scripts/28_reselect_backgrounds.py:25`, `scripts/28_reselect_backgrounds.py:78-87`). If validation fails, it silently restores the old window, including known-broken cases (`scripts/28_reselect_backgrounds.py:91-94`). The picker itself accepts any positive ordering without enforcing the 50-150 s rule or source separation (`scripts/30_background_picker.py:217-228`, `scripts/30_background_picker.py:384-406`). In the current clean ECSV, 114/418 pre-windows and 5/418 post-windows are shorter than 50 s; all five detectors of bn100614498 have a zero-width pre-window.

**Impact.** bn100614498 contributes 2/1,057 spectra with a one-sided background despite the stated two-sided method. More broadly, 28/106 bursts have at least one <50 s pre-window. The effect on model fractions is unquantified until refit with validated windows.

**Fix.** Reject zero/negative windows, enforce per-side widths or an explicit one-sided exception with provenance, run QC before fitting, and never fall back to a known-broken row without a hard failure.

### H4. Production Bayesian blocks use a Gaussian raw-count approximation, not a background-aware Poisson count likelihood

**Evidence.** Script 27 histograms raw events, converts counts to rates with `sqrt(max(count,1))` Gaussian errors, and invokes `fitness='measures'` (`scripts/27_reblock_all.py:46-51`). The fitted polynomial background is not evaluated or subtracted when finding change points; only a scalar rate estimated from the two windows is used for peak trimming/significance (`scripts/27_reblock_all.py:53-71`, `scripts/27_reblock_all.py:100-109`). This is not the background-subtracted Bayesian-block method described in the project rules, and it treats low-count Poisson cells as Gaussian point measurements.

**Impact.** All 1,057 time bins depend on this approximation. Constant background mainly shifts rates, but time-varying orbital background and low-count cells can change block boundaries and therefore every fitted spectrum and population count.

**Fix.** Use a count likelihood with exposure/background explicitly represented, or use 3ML's background-aware block construction and validate it by simulation. Persist the chosen fitness, p0, cell width, and source/background model per burst.

### H5. The headline Ep-kT relation mixes parameters from different model fits

**Evidence.** `Ep` is always taken from the standalone Band fit (`scripts/31_draft_numbers.py:73-85`, `scripts/31_draft_numbers.py:200-201`), while `kT` is taken from a decisive Band+BB or CPL+BB fit (`scripts/31_draft_numbers.py:92-112`). The per-burst Burgess test then correlates those two arrays directly (`scripts/31_draft_numbers.py:344-358`). Consequently, CPL+BB temperatures are paired with an unrelated standalone-Band Ep, and bins without a valid standalone Band fit are discarded even when the composite fit is valid.

**Impact.** The published `17/19 = 89%` positive-burst result becomes **22/26 = 85%** when each temperature is paired with the nonthermal peak from the same composite fit; individually significant positive bursts change from 12 to 11. The global rho changes from 0.72 (N=233) to 0.48 (N=301). For GRB 130427A, using the simultaneously fitted Band+BB Ep gives a D'Agostini slope about **1.00 +/- 0.04** on 24 error-usable Band+BB bins, rather than the paper's **0.88 +/- 0.07** (`paper/two_break.tex:456-460`).

**Fix.** For Band+BB use `BANDBB_EP`; for CPL+BB derive Ep from the fitted CPL parameters and propagate its full covariance. Never combine a component parameter with a different model's fit.

### H6. DSBPL optimizer failures remain common and there is no restart

**Evidence.** Every model is fit once (`scripts/10_spectral_fit_burst.py:601-612`); restart logic exists only for the two +BB models (`scripts/10_spectral_fit_burst.py:614-662`). Current outputs contain 132/992 finite DSBPL-vs-SBPL likelihood differences below -1, including 67 below -9.2 and a minimum of -395, which cannot represent the best optimum of the more flexible model.

**Impact.** The reported 14/108 = 13% decisive two-break fraction at the locked threshold is a lower limit of unknown size. Failures are concentrated enough to affect which high-S/N bins are testable.

**Fix.** Add DSBPL multi-starts seeded from the converged SBPL and physically ordered break grids, require the child optimum not to be worse than the parent beyond tolerance, and rerun the complete sample.

### H7. The nu_m-nu_c headline uses double-break parameters even when a second break is not required

**Evidence.** Any physically valid DSBPL contributes `xb` and `xp`, regardless of its improvement over SBPL (`scripts/31_draft_numbers.py:116-120`), and the population fit uses all finite pairs (`scripts/31_draft_numbers.py:238-256`). The D'Agostini likelihood also omits the covariance between the two break estimates even though they come from the same fit (`scripts/31_draft_numbers.py:222-236`).

**Impact.** The paper quotes rho=0.57, N=349 and slope 0.46+/-0.05 (`paper/two_break.tex:462-466`). Requiring the stated decisive second break leaves **26 pairs**, not 349, with rho=0.69; requiring both decisiveness and <100% marginal errors leaves 23 pairs with rho=0.75. The correlation survives, but its denominator and physical interpretation change substantially, and the slope/scatter uncertainty is understated without the within-fit covariance.

**Fix.** Label the 349-point result as an exploratory all-fit relation, make the decisive/constrained subset primary for physical claims, and store/use the joint covariance of `(xb,xp)` in the regression.

### H8. rsp2 fallback replaces time-dependent responses with one matrix for entire bursts

**Evidence.** On any response-coverage failure, the engine selects the single matrix with largest overlap with the full source span (`scripts/10_spectral_fit_burst.py:135-164`) and then uses that static response for every time bin (`scripts/10_spectral_fit_burst.py:204-228`). Current logs show this fallback for every detector of bn090829672, bn100130729, and bn150721242.

**Impact.** 32/1,057 bins across three bursts were fit with responses that need not correspond to each bin's spacecraft orientation. The impact on their parameters and model choices is unquantified.

**Fix.** Build a response per bin from the overlapping rsp2 matrices, or restrict each SpectrumLike to a matrix that covers that bin; record the selected matrix interval in metadata.

### H9. The locked Delta-AIC=10 framework is not the headline result

**Evidence.** The README locks decisiveness at Delta-AIC >=10 (`README.md:129-140`) but leads with the Delta-AIC>6 split (`README.md:17-21`). The population script computes both (`scripts/31_draft_numbers.py:176-186`), and the paper likewise headlines the >6 result (`paper/two_break.tex:435-445`).

**Impact.** The headline changes from **151/166 = 91% thermal-or-degenerate and 9% two-break** to the locked result **94/108 = 87% and 14/108 = 13%**: 58 fewer qualifying bins and a 4 percentage-point increase in the two-break fraction.

**Fix.** Use the >=10 split in the abstract, README, summary, and conclusions; retain >6 only as a labeled sensitivity analysis.

### H10. Fine-grid variability p0 is not calibrated for the data representation used

**Evidence.** Script 35 passes one row per 1-2 ms grid cell plus integer counts to Astropy's `fitness='events'` (`scripts/35_variability_bb.py:41-57`). In this API, the change-point prior is calibrated using the number of supplied time cells, not the number of photon events. Changing the arbitrary grid therefore changes both the candidate cells and the nominal p0 penalty; the method is not the grid-independent event-arrival analysis claimed in the docstring (`scripts/35_variability_bb.py:3-11`).

**Impact.** The paper's **11/106 bursts below 128 ms and 2 ms minimum** (`paper/two_break.tex:208-212`) is not a statistically calibrated false-alarm result and should not be used to validate 128 ms production binning.

**Fix.** Run event-mode blocks on actual photon arrival times, or use the regular/binned Poisson formulation with a prior calibrated by simulation for the exact grid, exposure, background, and trials across 106 bursts.

### H11. The master manifest reports the wrong reference detector for 35 bursts

**Evidence.** The manifest always writes the detector stored in `single_pulse_grbs.ecsv` as `reference_nai` (`scripts/38_build_manifest.py:20-27`, `scripts/38_build_manifest.py:41-47`). The fitting engine instead falls back to the approved detector with highest mean significance when that detector is unavailable (`scripts/10_spectral_fit_burst.py:117-132`). The manifest then searches the background table for the wrong detector and emits NaNs (`scripts/38_build_manifest.py:33-40`).

**Impact.** 35/106 manifest rows name a detector different from the actual `canonical_det`, and those same 35 rows have missing reference-detector background windows. The claimed full selection record is therefore false, although the total bin count remains correct.

**Fix.** Read `canonical_det` and `fit_dets` from each production JSON, join its actual background row, and fail manifest generation on missing provenance.

## MEDIUM

### M1. The physical-validity gate still silently assigns invalid winners in the engine

**Evidence.** If no fit passes the physical gate, `select_best` falls back to the minimum among all OK fits (`scripts/10_spectral_fit_burst.py:551-560`). Current data contain 43/1,057 such bins. Script 31 filters these winners later (`scripts/31_draft_numbers.py:86-91`), but the machine table exports the original `BEST_AIC_MODEL` unchanged (`scripts/33_machine_tables.py:47-56`).

**Impact.** Population numbers produced by script 31 are protected, but 43 machine-table rows contradict the paper's claim that no preferred model is assigned (`paper/two_break.tex:315-318`). Any downstream consumer that trusts `BEST_AIC_MODEL` is polluted.

**Fix.** Return `NONE_PHYSICAL`/blank from the engine and add explicit best-valid AIC/BIC columns; regenerate tables.

### M2. DSBPL/SBPL is not a regular Wilks-test pair as implemented

**Evidence.** The code labels DSBPL/SBPL as an LRT pair (`scripts/10_spectral_fit_burst.py:539-569`). The two functions use separately fixed smoothness parameterizations (`scripts/10_spectral_fit_burst.py:295-327`); when the extra break disappears, its location is unidentified, so standard Wilks regularity does not hold even if a limiting shape can be constructed.

**Impact.** The numerical `LRT>=14` condition is still equivalent to Delta-AIC>=10 for a two-parameter penalty, so current classification counts need not change. The claimed nominal LRT significance/d.o.f. interpretation is not defensible.

**Fix.** Describe this solely as an AIC comparison or calibrate the likelihood-ratio distribution by simulation.

### M3. Flux uncertainty propagation ignores parameter covariance and asymmetric errors

**Evidence.** Figure flux errors independently perturb Band parameters with symmetric Gaussian errors (`scripts/32_make_figures.py:82-103`). The fit engine stores MINOS asymmetric errors but no covariance (`scripts/10_spectral_fit_burst.py:404-445`). Independent draws are particularly inappropriate for correlated Band parameters `(alpha, Ep, beta, K)`.

**Impact.** Central fluxes are correct, but plotted flux intervals and masks can be too narrow or too broad; this affects the visible error bars and which points pass the <0.5 dex mask, not the rank-correlation central values.

**Fix.** Draw from the fitted covariance/posterior with bound-aware sampling, or label the current bars as diagonal-Hessian approximations.

### M4. LLE background windows are copied from the first NaI

**Evidence.** When LLE files exist, the engine reuses `nai_dets[0]` background windows rather than a LAT/LLE-specific good-time/background selection (`scripts/10_spectral_fit_burst.py:738-750`).

**Impact.** All 11 LLE bursts may have an LLE background interval chosen for a different instrument and field-of-view history. The direction and size of the spectral impact are unquantified.

**Fix.** Store and validate LLE-specific intervals/GTIs in the background catalog and manifest.

### M5. Resume logic can silently preserve stale or partial products

**Evidence.** Script 29 treats the mere existence of `spectral_fits.ecsv` as completion (`scripts/29_refit_clean.py:30-44`), ignores the subprocess return code, and launches all triggers even though `todo` is computed (`scripts/29_refit_clean.py:46-56`). Per-burst metadata records no input hashes, code revision, CALDB version, background file, or block file (`scripts/10_spectral_fit_burst.py:862-875`).

**Impact.** The current catalog happens to account exactly, but a future partial/human-background rerun can mix old and new bursts without detection.

**Fix.** Validate expected row count and fit status, fail on nonzero return codes, stamp complete provenance, and resume only when hashes match.

### M6. Hardcoded local paths prevent portable reproduction

**Evidence.** The driver hardcodes the Python environment and CALDB tree (`scripts/29_refit_clean.py:17-25`); scripts 31-35 and 38 hardcode the repository root (`scripts/31_draft_numbers.py:18-20`, `scripts/32_make_figures.py:20-22`, `scripts/33_machine_tables.py:12-15`, `scripts/35_variability_bb.py:19-20`, `scripts/38_build_manifest.py:12-16`).

**Impact.** The advertised pipeline cannot run unchanged outside the author's machine, and environment drift cannot be audited.

**Fix.** Resolve paths relative to each script/repository, accept environment paths through configuration, and record package/CALDB versions.

### M7. Legacy scripts and output roots remain easy to invoke accidentally

**Evidence.** The engine defaults to legacy blocks and `background_intervals_prototype.ecsv` unless overrides are supplied (`scripts/10_spectral_fit_burst.py:696-706`, `scripts/10_spectral_fit_burst.py:724-756`), while the repository retains scripts 24/25/26, old 04/05/06 flows, `.bak` engines, and top-level legacy block products. The production distinction exists only in script 29's arguments.

**Impact.** A direct engine run or old helper can silently generate results from provisional inputs under the same schema. This is a reproducibility/stale-mix risk rather than a demonstrated change to the current 1,057-bin catalog.

**Fix.** Make production inputs mandatory, archive legacy entry points outside `scripts/`, and embed an input-root label/hash in every output.

### M8. The automatic source-window algorithm can integrate positive noise as emission

**Evidence.** Script 28 estimates a scalar median background outside a peak-centered window, clips every negative residual to zero, and takes 5-95% of the remaining positive residual (`scripts/28_reselect_backgrounds.py:37-56`). Positive noise therefore accumulates while negative noise is discarded. The peak is selected from raw counts over a fixed -100 to 600 s grid (`scripts/28_reselect_backgrounds.py:40-48`).

**Impact.** The previously identified six pure-background source windows are no longer disjoint from catalog T90 in the current products, so that specific bug appears fixed. However, source widths and background placement can still be biased outward or toward a background feature, affecting all automatic backgrounds provisionally.

**Fix.** Fit the background first, retain signed residuals with uncertainty, identify a statistically significant connected emission region, and verify against multiple detectors.

### M9. The fine and production source windows can cross the nominal background boundary

**Evidence.** The emission-window expansion uses a hard-coded +/-0.5 s around cell centers and does not clamp to the input source gap (`scripts/27_reblock_all.py:53-67`). In the current manifest, bn130518580 begins 0.31 s before the recorded pre-background stop.

**Impact.** One burst's analysis interval overlaps its nominal background region; the effect is small in duration but violates manifest semantics.

**Fix.** Clamp `elo/ehi` to `[pre_stop, post_start]` and assert disjoint source/background intervals before fitting.

### M10. The alpha-max figure has clipped annotations

**Evidence.** Labels are placed at the current right x-limit and only afterward is the x-axis switched to logarithmic scale (`scripts/32_make_figures.py:263-273`). In the rendered PDF, all three physical-limit labels are clipped at the right edge.

**Impact.** Figure 4 is not submission-ready; no paper number changes.

**Fix.** Place labels in axes coordinates or add right margin/inside alignment after setting the log scale and final limits.

## LOW

### L1. BIC uses all stored channels rather than active channels

**Evidence.** `n_data` counts the full `observed_counts` arrays (`scripts/10_spectral_fit_burst.py:597-599`) after energy masks are applied elsewhere (`scripts/10_spectral_fit_burst.py:241-253`).

**Impact.** BIC penalties are slightly inflated; because model parameter-count differences are small and the same channels enter each model, the prior audit's estimated Delta-BIC shift (<0.4) remains negligible for headline decisions.

**Fix.** Count only active spectral bins used by the likelihood.

### L2. No automated regression tests protect the scientific contracts

**Evidence.** Core thresholds, model mappings, provenance, catalog accounting, and known anchor bursts are implemented only in executable scripts (for example `scripts/31_draft_numbers.py:69-141` and `scripts/38_build_manifest.py:19-57`), with no test suite in the repository.

**Impact.** Fixed issues can regress silently; no current paper number changes.

**Fix.** Add tests for model nesting/mappings, factor-of-two convention, validity fallback, decisive-BB gating, 106/1,057 accounting, manifest-vs-JSON detector equality, and anchor-burst correlations.

## Confirmed Correct Or Fixed

- **Catalog accounting is exact.** Script 31 combines only real blocks (`scripts/31_draft_numbers.py:22-31`); current clean blocks, per-burst fits, and machine tables each contain 106 bursts and 1,057 unique bins. The manifest's `n_bins` sum is also 1,057 (`scripts/38_build_manifest.py:26-32`).
- **The -2 log-likelihood convention is correct.** The engine explicitly doubles 3ML's current minimum (`scripts/10_spectral_fit_burst.py:410-418`) and computes AIC/BIC as `N2LL+2k` and `N2LL+k ln N` (`scripts/10_spectral_fit_burst.py:453-466`). Model spectral parameter counts are correct; omitted cross-normalization parameters are common to all compared models and therefore cancel in AIC/BIC differences.
- **The code computes LRT differences only for the three intended parent/child pairs** (`scripts/10_spectral_fit_burst.py:562-576`); the central +BB-versus-DSBPL decision is made with AIC, not an LRT (`scripts/31_draft_numbers.py:121-136`). The DSBPL/SBPL calibration caveat is separately reported above.
- **The physical gate itself correctly checks bounds and DSBPL ordering** (`scripts/10_spectral_fit_burst.py:495-536`). Script 31 now protects population counts from the engine's no-physical fallback (`scripts/31_draft_numbers.py:86-91`).
- **The decisive-BB gate is fixed.** kT now requires a valid +BB fit and `LRT>=14`, exactly equivalent to Delta-AIC>=10 for two added parameters (`scripts/31_draft_numbers.py:92-105`). The old `LRT>0` contamination is no longer present.
- **BB multi-start is active and keep-best.** It restarts railed/insignificant +BB fits from three seeds and retains only a lower N2LL (`scripts/10_spectral_fit_burst.py:614-662`). Some OK fits still sit near kT=1 keV, but the validity and significance gates prevent them from entering decisive-BB population numbers.
- **The rise-phase HTS/IT classifier is order-independent.** It classifies from pre-peak Ep behavior with an explicit fallback (`scripts/31_draft_numbers.py:298-327`) and reports the old order-sensitive rules only as sensitivity output (`scripts/31_draft_numbers.py:328-342`). Current result: 48/76 HTS, 19/76 IT, 9/76 ambiguous.
- **A genuine D'Agostini likelihood is now implemented.** The code includes free intrinsic scatter and both x/y marginal errors (`scripts/31_draft_numbers.py:222-236`, `scripts/31_draft_numbers.py:253-275`). The remaining covariance/sample-gating limitations are reported in H7.
- **The K-edge code and manuscript now agree at 33-40 keV.** The active NaI ranges are 8.1-33 and 40-900 keV (`scripts/10_spectral_fit_burst.py:67-71`), matching the manuscript (`paper/two_break.tex:169-173`). BGO and LLE fit ranges also match the stated 0.3-40 MeV and 30-100 MeV bands.
- **The prior major correlation-figure defects are fixed.** The 130427A uncertainty mask is applied to both series (`scripts/32_make_figures.py:218-227`), energy/photon flux panels are now side by side rather than twinned (`scripts/32_make_figures.py:228-249`), PDF fonts are Type 42 (`scripts/32_make_figures.py:25-34`), and the evolution right column has adequate spacing (`scripts/32_make_figures.py:170-195`).
- **Machine tables are deterministic reformats with matching row counts.** They read the combined production catalog and export 106 per-burst rows and 1,057 unique per-bin rows (`scripts/33_machine_tables.py:15-20`, `scripts/33_machine_tables.py:24-56`). The invalid-winner semantic issue is reported in M1.

## Required Disposition Before Submission

1. Rebuild and freeze the 106-burst sample with a faithful, documented morphology implementation.
2. Connect the human background output to a fresh, provenance-stamped rerun and enforce background QC.
3. Replace or validate the production and fine-grid Bayesian-block likelihoods.
4. Add DSBPL restarts and rerun all spectra.
5. Recompute Ep-kT with matched composite parameters and nu_m-nu_c with decisive/constrained gating plus covariance.
6. Make Delta-AIC>=10 the headline framework, regenerate all numbers/tables/figures, and rebuild the manifest from actual per-burst metadata.
